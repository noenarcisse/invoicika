# Phases
La campagne de test va se dérouler en 2 phases et une phase **bonus**

# Phase 1 : Scouting
Cette phase vise à observer l'application afin d'en retirer des règles métiers, objectifs et tout type de documentation utile pour le métier que l'application va devoir servir.
C'est durant cette phase que son préparé les documents de stratégie, planning et la mise en place des outils (JIRA, repository de test, etc.)

Elle n'est pas compté dans les sprints et est orienté gestion de projet.

- Identification de bugs trouvables en exploration
- Vérification des critères d'entrée des features, passage en bloqué si la feature n'est pas prête à être testée
- Etablir les règles métiers
- Préparation des documents et outils nécéssaires à réaliser le travail
- Recherche de documentation complémentaire

# Phase 2 : Tests

Cette phase se concentre sur l'élaboration et l'exécution des tests visant à tester l'application. Elle se déroule par sprints d'une semaine. Le but majeur de ces sprints sera avant tout de voir ce qui est faisable par rapport à la
Les conditions de sortie de la charte de test globale ou la fin de la deadline annonce la fin de cette phase.

- Prepation environnement intial, jeux de données, états de base de données éventuels
- Design de tests, cas de tests, scénarios
- Implémentation des cas de tests
- Exécution de tests
- Rapports de tests

# Phase 3 : Bonus

Cette phase bonus permet d'étendre les tests en dehors de l'application sur le produit délivré (la facture PDF).
Elle se déroule en sprints et ne peut être lancée que sous des conditions bien précises : l'ensemble des critères de sortie sur les features à tester est rempli et il reste du temps suffisant dans le planning pour lancer la phase 3.
